## 1. Wheel Encoder 동작원리

### 개요

Wheel Encoder는 바퀴의 회전량을 측정하여 로봇의 이동 거리와 방향을 추정하는 센서이다.

### 종류

#### 1.1 증분형 엔코더 (Incremental Encoder)

- 회전 디스크에 일정 간격으로 슬롯(구멍)이 뚫려 있으며, 광학 센서(발광부 + 수광부)가 슬롯을 통과하는 빛의 차단 여부를 감지한다.
- 슬롯을 통과할 때마다 **펄스 신호** 발생
- 펄스 수를 누적하여 회전량(각도) 계산
- **A상·B상** 두 채널을 사용해 회전 방향도 판별 (위상차 90°)
- 분해능: 1회전당 펄스 수 (PPR, Pulses Per Revolution)

```
회전 각도 θ = (펄스 수 / PPR) × 360°
이동 거리 d = θ × r  (r: 바퀴 반지름)
```

#### 1.2 절대형 엔코더 (Absolute Encoder)

- 각 위치마다 고유한 코드를 부여 (그레이 코드 등)
- 전원이 꺼져도 절대 위치 정보 유지
- 구조가 복잡하고 비용이 높음

#### 1.3 홀 효과 엔코더 (Hall Effect Encoder)

- 자석과 홀 센서를 이용
- 비접촉 방식으로 내구성 우수
- 저해상도지만 모터 제어에 적합

### 동작 흐름

```
바퀴 회전 → 슬롯 디스크 회전 → 광 차단 → 펄스 발생 → 카운터 누적 → 거리/속도 계산
```

## 2. Wheel Encoder 기반 Odometry의 문제점

Odometry는 엔코더 데이터를 적분하여 로봇의 위치를 추정하는 방법이다.

### 2.1 슬립 (Wheel Slip)

- 바퀴가 미끄러지면 실제 이동 없이 엔코더 값이 변화
- 젖은 바닥, 경사면, 급가속/급제동 시 발생
- **결과**: 과도한 이동 거리 추정

### 2.2 오차의 누적 (Cumulative Error)

- 매 스텝의 작은 오차가 적분되면서 **무한히 축적**
- 주행 거리에 비례하여 위치 오차가 증가
- 장거리 주행 시 위치 오차가 수 미터 이상 될 수 있음

```
x(t) = x₀ + Σ Δx_i   ← 오차가 누적됨
```

### 2.3 바퀴 반지름 오차

- 타이어 마모, 공기압 변화로 실제 반지름이 변동
- 캘리브레이션 값과 실제 값의 차이가 오차 유발

### 2.4 베이스라인(Wheelbase) 오차

- 두 바퀴 사이의 거리(L) 측정 오차
- 회전 각도 계산에 직접적으로 영향

```
Δθ = (d_R - d_L) / L   ← L의 오차가 방향 오차 유발
```

### 2.5 비평탄 지형

- 울퉁불퉁한 지면에서 바퀴가 들리거나 기울어짐
- 2D 평면 가정이 깨져 3D 오차 발생

### 2.6 환경적 요인

| 요인 | 영향 |
|------|------|
| 경사면 | 중력 성분으로 인한 슬립 |
| 모래/흙 | 바퀴 파고들기로 유효 반지름 변화 |
| 장애물 충돌 | 갑작스러운 위치 오차 |

## 3. IMU 동작원리

IMU(Inertial Measurement Unit)는 **가속도계(Accelerometer)**, **자이로스코프(Gyroscope)**, 선택적으로 **지자기 센서(Magnetometer)**로 구성된다.

### 3.1 가속도계 (Accelerometer)

#### 동작 원리

- **MEMS(Micro Electro Mechanical Systems)** 기술 기반
- 내부에 **스프링-질량 시스템** 구조 존재
- 가속도가 가해지면 질량체가 변위 → **정전용량 변화** 감지

```
F = ma  →  a = F/m
정전용량 변화 ΔC ∝ 변위 x ∝ 가속도 a
```

#### 측정값

- 3축(x, y, z) 선형 가속도 측정 [m/s²]
- 중력 가속도(g = 9.81 m/s²) 포함

### 3.2 자이로스코프 (Gyroscope)

#### 동작 원리

- **코리올리 효과(Coriolis Effect)** 이용
- 진동하는 MEMS 구조물이 회전할 때 코리올리 힘 발생
- 이 힘을 정전용량 변화로 측정

```
F_coriolis = 2m(v × ω)
정전용량 변화 ΔC ∝ 각속도 ω
```

#### 측정값

- 3축 각속도 측정 [rad/s 또는 °/s]

### 3.3 지자기 센서 (Magnetometer)

- **홀 효과** 또는 **자기저항 효과** 이용
- 지구 자기장 방향으로 절대 방위각 추정
- 3축 자기장 강도 측정 [μT]

### 3.4 IMU 데이터 융합

```
가속도계 → 속도 적분 → 위치 추정
자이로스코프 → 각도 적분 → 자세(Roll, Pitch, Yaw) 추정
지자기 센서 → 절대 방위각 보정
```

### IMU 좌표계

```
         z (위)
         |
         |______ y (오른쪽)
        /
       x (앞)

Roll  : x축 회전
Pitch : y축 회전
Yaw   : z축 회전
```

## 4. IMU 기반 Odometry의 문제점

### 4.1 드리프트 (Drift)

- 각속도를 **적분**하여 각도를 추정하므로, 작은 바이어스 오차가 시간에 따라 누적
- 시간이 지날수록 추정 위치/방향이 실제와 점점 벌어짐

```
θ(t) = ∫ω(t)dt   ← 바이어스 ε가 있으면
θ(t) = ∫(ω(t) + ε)dt = θ_true(t) + ε·t   → 선형 드리프트
```

### 4.2 바이어스 불안정성 (Bias Instability)

- 센서 바이어스가 온도, 시간에 따라 변함
- 공장 캘리브레이션 값이 사용 환경과 다를 수 있음

### 4.3 이중 적분 문제

- 위치 추정을 위해 가속도를 **두 번 적분**
- 오차가 **제곱**으로 증가

```
a(t) → v(t) = ∫a(t)dt  (1차 적분)
v(t) → x(t) = ∫v(t)dt  (2차 적분)
오차 ε_a → 위치 오차 ∝ ε_a · t²
```

### 4.4 진동 및 외부 충격

- 고주파 진동이 가속도계에 영향
- 로봇 모터, 노면 충격 등으로 노이즈 증가

### 4.5 중력 분리 문제

- 가속도계는 중력과 실제 운동 가속도를 **합산**하여 측정
- 경사면에서 중력 성분 분리 오류 발생

### 4.6 자기 간섭 (지자기 센서)

- 주변 금속, 전자기기로 인해 지자기 측정 왜곡
- 실내 환경에서 절대 방위각 오차 급증

### 요약 비교

| 문제 | Wheel Encoder | IMU |
|------|:---:|:---:|
| 슬립 오차 | ✅ 심각 | ❌ 무관 |
| 드리프트 | ✅ 있음 | ✅ 매우 심각 |
| 비평탄 지형 | ✅ 영향 | △ 일부 영향 |
| 고속 회전 측정 | ❌ 한계 | ✅ 우수 |
| 정적 위치 유지 | ✅ 가능 | ❌ 드리프트 |

## 5. SLAM에서 사용되는 센서 비교

SLAM(Simultaneous Localization and Mapping)에서는 다양한 센서가 사용되며, 각각 고유한 특성을 가진다.

### 5.1 센서별 특성 비교표

| 특성 | 2D LiDAR | 3D LiDAR | RGB 카메라 | RGB-D 카메라 | IMU | Wheel Encoder |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| **측정 방식** | ToF/위상 | ToF | 수동 | 적외선+RGB | 관성 | 광학/자기 |
| **출력 데이터** | 2D 점군 | 3D 점군 | 2D 영상 | 2D+깊이 | 가속도/각속도 | 펄스 수 |
| **거리 측정** | ✅ 직접 | ✅ 직접 | ❌ 간접 | ✅ 직접 | ❌ | ✅ 간접 |
| **텍스처 정보** | ❌ | ❌/△ | ✅ 풍부 | ✅ 풍부 | ❌ | ❌ |
| **실외 사용** | ✅ | ✅ | ✅ | △ (IR 간섭) | ✅ | ✅ |
| **조명 의존성** | ✅ 무관 | ✅ 무관 | ❌ 의존 | △ | ✅ 무관 | ✅ 무관 |
| **비용** | 저~중 | 매우 고 | 저 | 중 | 중 | 저 |
| **데이터 양** | 적음 | 많음 | 많음 | 많음 | 매우 적음 | 매우 적음 |
| **업데이트 속도** | 10~40Hz | 10~20Hz | 30~120Hz | 30~60Hz | 100~1000Hz | 수백~수kHz |

### 5.2 센서별 상세 특징

#### 2D LiDAR

```
장점:
  - 정확한 거리 측정 (오차 ~1-3cm)
  - 조명/색상 무관
  - 안정적인 데이터
  - 처리 부하 낮음

단점:
  - 단일 평면만 스캔
  - 계단, 경사면 처리 어려움
  - 유리/거울에 반사 오류

대표 제품: SICK LMS, Hokuyo URG, RPLiDAR
```

#### 3D LiDAR

```
장점:
  - 3D 공간 완전 복원
  - 원거리 측정 (100m 이상)
  - 높은 정밀도

단점:
  - 매우 높은 비용 (수천만 원)
  - 대용량 데이터 처리 필요
  - 낮은 해상도 (비용 대비)
  - 비·안개에 영향

대표 제품: Velodyne VLP-16/32, Ouster OS1, Livox Mid-360
```

#### 단안 카메라 (Monocular Camera)

```
장점:
  - 가장 저렴
  - 풍부한 텍스처 정보
  - 작고 가벼움

단점:
  - 깊이 정보 없음 (단안)
  - 스케일 모호성 (Monocular SLAM)
  - 조명 변화, 모션 블러에 취약
  - 특징점 없는 환경에서 실패

대표 알고리즘: ORB-SLAM, DSO, MonoDepth
```

#### RGB-D 카메라 (Depth Camera)

```
장점:
  - 색상 + 깊이 동시 획득
  - 밀도 높은 3D 복원
  - 저렴한 3D 측정

단점:
  - 실외 햇빛에서 IR 간섭
  - 측정 범위 제한 (~5m)
  - 투명/반사 물체 측정 불가

대표 제품: Intel RealSense, Microsoft Kinect, ASUS Xtion
```

#### IMU

```
장점:
  - 매우 높은 업데이트 속도 (100~1000Hz)
  - 빠른 동작 추적
  - 다른 센서와 융합 시 강력

단점:
  - 단독 사용 시 드리프트 심각
  - 반드시 다른 센서와 융합 필요

융합 방식: Visual-Inertial Odometry (VIO), LiDAR-IMU
```

### 5.3 센서 융합 전략

```
LiDAR + IMU     → LIO-SAM, LiDAR-Inertial Odometry
Camera + IMU    → VINS-Mono, MSCKF, ORB-SLAM3
LiDAR + Camera  → LVI-SAM, CamVox
All sensors     → 최고의 강건성, 최고의 복잡도
```

## 6. 필터 기반 vs 그래프 기반 SLAM 비교

### 6.1 필터 기반 SLAM (Filter-based SLAM)

#### 대표 알고리즘

- **EKF-SLAM** (Extended Kalman Filter)
- **UKF-SLAM** (Unscented Kalman Filter)
- **Particle Filter SLAM** (FastSLAM, GMapping)

#### 동작 원리

```
[예측 단계]
x̂(t|t-1) = f(x̂(t-1|t-1), u(t))     ← 모션 모델
P(t|t-1) = F·P(t-1|t-1)·Fᵀ + Q      ← 공분산 예측

[업데이트 단계]
K = P(t|t-1)·Hᵀ·(H·P(t|t-1)·Hᵀ + R)⁻¹   ← 칼만 이득
x̂(t|t) = x̂(t|t-1) + K·(z(t) - h(x̂))    ← 상태 업데이트
P(t|t) = (I - K·H)·P(t|t-1)               ← 공분산 업데이트
```

#### 특징

| 항목 | 내용 |
|------|------|
| **상태 표현** | 로봇 포즈 + 모든 랜드마크를 단일 상태벡터로 표현 |
| **계산 복잡도** | O(n²) ~ O(n³) (n: 랜드마크 수) |
| **메모리** | 공분산 행렬 크기 O(n²) |
| **실시간성** | 소규모 환경에서 실시간 가능 |
| **과거 데이터** | 현재 상태만 유지, 과거 경로 수정 불가 |
| **루프 클로저** | 처리 어렵고 오차 전파 문제 |

#### 장단점

```
✅ 장점
  - 실시간 처리 적합
  - 수학적으로 명확한 확률 모델
  - 소규모 환경에서 효과적

❌ 단점
  - 랜드마크 수 증가 시 계산량 폭발
  - 선형화 오류 (EKF)
  - 루프 클로저 처리 비효율
  - 대규모 환경에 부적합
```

### 6.2 그래프 기반 SLAM (Graph-based SLAM)

#### 대표 알고리즘

- **g2o**, **GTSAM**, **Ceres Solver** 기반
- **Cartographer** (Google), **RTAB-Map**, **ORB-SLAM2/3**

#### 동작 원리

```
포즈 그래프 구성:
  노드(Node)   : 로봇의 각 시점의 포즈 x₁, x₂, ..., xₙ
  엣지(Edge)   : 두 포즈 사이의 상대 변환 측정값 (제약 조건)

비용 함수 최적화:
  E(x) = Σᵢⱼ eᵢⱼ(xᵢ, xⱼ)ᵀ · Ωᵢⱼ · eᵢⱼ(xᵢ, xⱼ)

  eᵢⱼ : 측정값과 예측값의 차이 (오차 함수)
  Ωᵢⱼ : 정보 행렬 (측정 불확실성의 역수)

최적화 방법:
  x* = argmin E(x)  ← Gauss-Newton, Levenberg-Marquardt
```

#### 그래프 구조 예시

```
x₁ ──odometry── x₂ ──odometry── x₃ ──odometry── x₄
 \                                               /
  └──────────── loop closure edge ─────────────┘
  (루프 클로저 감지 시 엣지 추가 → 전체 그래프 최적화)
```

#### 특징

| 항목 | 내용 |
|------|------|
| **상태 표현** | 포즈 그래프 (노드 = 포즈, 엣지 = 제약) |
| **계산 복잡도** | 최적화: O(n) ~ O(n^1.5) (희소 행렬 이용) |
| **메모리** | 모든 포즈와 엣지 저장 |
| **실시간성** | 프론트엔드(실시간) + 백엔드(배치 최적화) 분리 |
| **과거 데이터** | 전체 경로 재최적화 가능 |
| **루프 클로저** | 자연스럽게 처리, 전역 일관성 확보 |

#### 장단점

```
✅ 장점
  - 대규모 환경에 적합
  - 루프 클로저 효과적 처리
  - 전체 경로 일관성 확보
  - 희소 행렬로 효율적 최적화

❌ 단점
  - 초기에는 오프라인 처리 필요
  - 잘못된 루프 클로저가 전체를 망침
  - 구현 복잡도 높음
```

---

### 6.3 필터 기반 vs 그래프 기반 종합 비교

| 비교 항목 | 필터 기반 SLAM | 그래프 기반 SLAM |
|-----------|:---:|:---:|
| **대표 알고리즘** | EKF-SLAM, FastSLAM | g2o, Cartographer, ORB-SLAM |
| **환경 규모** | 소규모 | 대규모 |
| **계산 복잡도** | O(n²) 이상 | O(n) ~ O(n^1.5) |
| **루프 클로저** | 어려움 | 효과적 |
| **정확도** | 중간 | 높음 |
| **실시간 처리** | 적합 | 프론트/백엔드 분리 |
| **과거 경로 수정** | 불가 | 가능 |
| **메모리 사용** | 현재 상태만 | 전체 경로 |

## 7. 영상 특징점 매칭 기법

### 7.1 특징점 매칭의 필요성

- 카메라 SLAM에서 서로 다른 프레임 사이의 **대응점 찾기**가 핵심
- 특징점 = 이미지에서 코너, 엣지, 블롭 등 **독특한 위치**

### 7.2 특징점 검출 알고리즘

#### Harris Corner Detector

```
동작 원리:
  - 픽셀 주변 윈도우를 이동시켰을 때 모든 방향으로 강도 변화가 큰 점
  - M = Σ[Ix², IxIy; IxIy, Iy²]  (구조 텐서)
  - R = det(M) - k·trace(M)²
  - R > threshold → 코너

특징: 회전 불변, 스케일 변환에 취약
```

#### FAST (Features from Accelerated Segment Test)

```
동작 원리:
  - 중심 픽셀 주위 16개 픽셀 원 검사
  - 연속된 n개 픽셀이 중심보다 밝거나 어두우면 코너
  - 매우 빠른 속도 (실시간 처리 가능)

특징: 빠름, 노이즈에 민감, 스케일/회전 불변성 없음
```

### 7.3 기술자 (Descriptor) 알고리즘

#### SIFT (Scale-Invariant Feature Transform)

```
동작 원리:
  1. DoG(Difference of Gaussians)로 스케일-공간 극값 검출
  2. 키포인트 방향 할당 (지배적 그래디언트 방향)
  3. 16×16 패치를 4×4 셀로 나누어 각 셀에서 8방향 히스토그램
  4. 128차원 기술자 벡터 생성

불변성:
  ✅ 스케일 불변
  ✅ 회전 불변
  ✅ 조명 변화에 강건
  ❌ 계산 비용 높음 (특허 만료)
```

#### SURF (Speeded Up Robust Features)

```
동작 원리:
  - SIFT의 속도 개선 버전
  - Hessian 행렬 근사로 키포인트 검출
  - Haar Wavelet 응답으로 64차원 기술자

특징:
  ✅ SIFT보다 3~7배 빠름
  ✅ 스케일/회전 불변
  ❌ SIFT보다 정확도 낮음
```

#### ORB (Oriented FAST and Rotated BRIEF)

```
동작 원리:
  - FAST 코너 검출 + 해리스 점수로 상위 N개 선택
  - 강도 중심(Intensity Centroid)으로 방향 계산
  - rBRIEF: 회전 보정된 BRIEF 기술자 (256비트 이진 문자열)

이진 기술자 매칭:
  - 해밍 거리(Hamming Distance)로 빠른 매칭 가능
  - XOR 연산 후 비트 카운트

특징:
  ✅ 매우 빠름 (실시간 SLAM에 적합)
  ✅ 특허 없음 (무료)
  ✅ 스케일/회전 불변
  △ 블러, 조명 변화에 SIFT보다 약함

대표 사용: ORB-SLAM2/3
```

#### BRIEF (Binary Robust Independent Elementary Features)

```
동작 원리:
  - 패치 내 랜덤 픽셀 쌍 비교
  - p(x) > p(y) → 1, 아니면 0 (이진 기술자)
  - 256비트 벡터

특징:
  ✅ 매우 빠른 계산 및 매칭
  ❌ 회전/스케일 불변성 없음
```

### 7.4 매칭 방법

#### Brute-Force Matching

```
- 모든 기술자 쌍에 대해 거리 계산
- 최근접 이웃 선택
- 복잡도: O(n²)
- 부동소수 기술자: L2 거리
- 이진 기술자: 해밍 거리
```

#### FLANN (Fast Library for Approximate Nearest Neighbors)

```
- KD-Tree, LSH 등 근사 최근접 이웃 탐색
- 복잡도: O(n log n)
- 대용량 데이터에서 BF보다 빠름
- 약간의 정확도 손실
```

#### Lowe's Ratio Test

```
매칭 품질 향상 기법:
  - 가장 가까운 이웃 d₁과 두 번째 d₂ 비교
  - d₁/d₂ < 0.7 이면 유효 매칭
  - 애매한 매칭 제거 → 오매칭 감소
```

### 7.5 기법 비교 요약

| 기법 | 검출기 | 기술자 | 속도 | 정확도 | 스케일 불변 | 회전 불변 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| SIFT | DoG | 128D float | 느림 | 매우 높음 | ✅ | ✅ |
| SURF | Hessian | 64D float | 중간 | 높음 | ✅ | ✅ |
| ORB | FAST+Harris | 256bit | 매우 빠름 | 중간 | ✅ | ✅ |
| BRIEF | - | 256bit | 매우 빠름 | 중간 | ❌ | ❌ |
| FAST | FAST | - | 가장 빠름 | - | ❌ | ❌ |

## 8. 라이다 특징점 매칭 기법

### 8.1 개요

라이다는 3D 점군(Point Cloud)을 생성한다. 점군 매칭으로 로봇의 이동량을 추정한다.

### 8.2 ICP (Iterative Closest Point)

```
동작 원리:
  1. 소스(Source) 점군과 타겟(Target) 점군 준비
  2. 각 소스 포인트에서 최근접 타겟 포인트 탐색
  3. 대응 쌍에 대해 변환 행렬 (R, t) 추정 (최소제곱)
  4. 소스 점군에 변환 적용
  5. 수렴할 때까지 반복

수식:
  E(R, t) = Σᵢ ||pᵢ - (R·qᵢ + t)||²  → 최소화

수렴 조건:
  ||변환 변화량|| < ε

특징:
  ✅ 구현 단순
  ✅ 밀도 높은 점군에서 정확
  ❌ 초기 추정값 필요 (수렴 범위 좁음)
  ❌ 계산 비용 높음 O(n log n) ~ O(n²)
  ❌ 아웃라이어에 민감
```

### 8.3 NDT (Normal Distributions Transform)

```
동작 원리:
  1. 타겟 점군을 3D 격자(Voxel)로 분할
  2. 각 셀에서 점들의 평균 μ과 공분산 Σ 계산 (정규분포)
  3. 소스 점들이 각 셀의 정규분포에 얼마나 잘 맞는지 점수화
  4. 점수를 최대화하는 변환 (R, t) 탐색

스코어 함수:
  s(x) = Σᵢ exp(-(pᵢ' - μ)ᵀ · Σ⁻¹ · (pᵢ' - μ) / 2)

특징:
  ✅ ICP보다 빠름
  ✅ 아웃라이어에 강건
  ✅ 해상도 조절 가능
  ❌ 격자 크기 파라미터 선택 중요
  ❌ 평탄한 구조에서 약함

대표 사용: Autoware의 NDT 매칭
```

### 8.4 LOAM (LiDAR Odometry and Mapping)

```
핵심 아이디어:
  라이다 스캔에서 엣지(Edge)와 평면(Planar) 특징점 추출

특징점 추출:
  - 곡률(Curvature) c = (1/|S|·||rᵢ||) · ||Σⱼ∈S (rⱼ - rᵢ)||
  - c 큰 점 → 엣지 특징점
  - c 작은 점 → 평면 특징점

매칭:
  - 엣지 ↔ 엣지 라인 대응
  - 평면 ↔ 평면 패치 대응
  - 각각에 대해 거리 최소화

시스템 구조:
  LiDAR Odometry (고주파, 저정확도)
       ↓
  LiDAR Mapping (저주파, 고정확도)

특징:
  ✅ 높은 정확도
  ✅ 실시간 처리
  ✅ 대표적인 LiDAR SLAM 기반

파생 알고리즘: LeGO-LOAM, LIO-SAM, LOAM-Livox
```

### 8.5 GICP (Generalized ICP)

```
동작 원리:
  - 일반 ICP의 확장 버전
  - 각 점에서 로컬 표면의 공분산 행렬 추정
  - 점-점이 아닌 분포-분포 간 거리 최소화

비용 함수:
  E(T) = Σᵢ (bᵢ - T·aᵢ)ᵀ · (Bᵢ + T·Aᵢ·Tᵀ)⁻¹ · (bᵢ - T·aᵢ)

특징:
  ✅ ICP보다 노이즈에 강건
  ✅ 수렴 안정성 향상
  ❌ 공분산 계산 비용
```

### 8.6 3D 라이다 기법 비교

| 기법 | 속도 | 정확도 | 강건성 | 특징 |
|------|:---:|:---:|:---:|------|
| ICP | 중간 | 높음 | 낮음 | 기본 매칭, 초기값 필요 |
| NDT | 빠름 | 높음 | 중간 | 격자 기반, 실용적 |
| LOAM | 빠름 | 매우 높음 | 높음 | 특징점 기반, 현재 표준 |
| GICP | 중간 | 매우 높음 | 높음 | 분포 기반, 정밀 매칭 |
| LeGO-LOAM | 매우 빠름 | 높음 | 높음 | 경량화 LOAM |

## 9. 변환행렬 (회전이동 & 평행이동)

### 9.1 2D 변환

#### 2D 평행이동 (Translation)

$$\begin{bmatrix} x' \\ y' \end{bmatrix} = \begin{bmatrix} x \\ y \end{bmatrix} + \begin{bmatrix} t_x \\ t_y \end{bmatrix}$$

동차 좌표계(Homogeneous Coordinates)로 표현:

```
[x']   [1  0  tx] [x]
[y'] = [0  1  ty] [y]
[1 ]   [0  0  1 ] [1]
```

#### 2D 회전이동 (Rotation)

회전 행렬 (반시계 방향, 각도 θ):

```
[x']   [cos θ  -sin θ] [x]
[y'] = [sin θ   cos θ] [y]
```

동차 좌표계 통합 표현:

```
[x']   [cos θ  -sin θ  tx] [x]
[y'] = [sin θ   cos θ  ty] [y]
[1 ]   [0       0      1 ] [1]
```

### 9.2 3D 변환

#### 3D 기본 회전 행렬

**X축 회전 (Roll, φ):**
```
Rx(φ) = [1    0       0   ]
        [0  cos φ  -sin φ  ]
        [0  sin φ   cos φ  ]
```

**Y축 회전 (Pitch, θ):**
```
Ry(θ) = [ cos θ  0  sin θ]
        [  0     1    0   ]
        [-sin θ  0  cos θ ]
```

**Z축 회전 (Yaw, ψ):**
```
Rz(ψ) = [cos ψ  -sin ψ  0]
        [sin ψ   cos ψ  0]
        [0       0      1]
```

#### 3D 합성 회전

```
R = Rz(ψ) · Ry(θ) · Rx(φ)   (ZYX Euler 순서, 로봇에서 일반적)
```

> ⚠️ **주의**: 행렬 곱셈은 교환법칙 불성립 → 순서가 결과에 영향

#### 회전 행렬의 성질

```
1. 직교 행렬: R·Rᵀ = I  (역행렬 = 전치행렬)
2. 행렬식: det(R) = +1
3. 열벡터: 서로 직교하는 단위벡터
4. 역회전: R⁻¹ = Rᵀ  (역변환이 전치)
```

### 9.3 동차 변환행렬 (Homogeneous Transformation Matrix)

3D 회전 + 평행이동을 4×4 행렬로 통합:

```
T = [R  t] = [r₁₁ r₁₂ r₁₃ tx]
    [0  1]   [r₂₁ r₂₂ r₂₃ ty]
             [r₃₁ r₃₂ r₃₃ tz]
             [0   0   0   1 ]

여기서:
  R ∈ SO(3): 3×3 회전 행렬
  t ∈ ℝ³:   3×1 평행이동 벡터
```

#### 좌표 변환

```
점 p를 프레임 A에서 프레임 B로 변환:

[pB]   [R  t] [pA]
[1 ] = [0  1] [1 ]

pB = R·pA + t
```

#### 역변환

```
T⁻¹ = [Rᵀ  -Rᵀ·t]
      [0    1    ]
```

### 9.4 변환 합성 (Chaining Transformations)

```
T₁₃ = T₁₂ · T₂₃

예: 로봇 기준 → 카메라 기준 → 월드 기준
T_world_robot = T_world_camera · T_camera_robot
```

### 9.5 SE(3)와 SO(3)

| 군(Group) | 의미 | 원소 | 자유도 |
|-----------|------|------|:---:|
| **SO(3)** | Special Orthogonal Group | 3D 회전 행렬 R | 3 |
| **SE(3)** | Special Euclidean Group | 동차 변환행렬 T = [R, t] | 6 |

### 9.6 회전 표현 방법 비교

| 표현 방법 | 차원 | 장점 | 단점 |
|-----------|:---:|------|------|
| **회전 행렬** | 9 (3×3) | 직관적, 합성 쉬움 | 중복 파라미터, 짐발락 없음 |
| **오일러 각도** | 3 | 직관적 이해 | 짐발락(Gimbal Lock) 발생 |
| **쿼터니언** | 4 | 짐발락 없음, 보간 쉬움 | 직관적이지 않음 |
| **축-각도** | 3+1 | 물리적 직관 | 특이점 존재 |
| **로드리게스 벡터** | 3 | 최소 파라미터 | 큰 각도에서 불안정 |

#### 쿼터니언 (Quaternion)

```
q = w + xi + yj + zk = [w, x, y, z]ᵀ

조건: w² + x² + y² + z² = 1

회전 행렬과의 관계:
R = (w² + x² - y² - z²    2(xy - wz)        2(xz + wy)    )
    (2(xy + wz)            w² - x² + y² - z²  2(yz - wx)   )
    (2(xz - wy)            2(yz + wx)        w² - x² - y² + z²)
```
